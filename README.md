# AI 求职工作台 · AI Job Application Workbench

> 一条端到端求职自动化管道：**采集招聘信息源 → 清洗去重入库 → 解析目标 JD → 对个人经历库加权匹配 → 自动生成定制版简历与技能缺口报告。**
> 以 AI 辅助开发（vibe coding）完成：需求定义、数据口径、验收标准与迭代由人负责，工程实现由 AI agent 执行。

## 目录结构

```
ai-job-workbench/
├── data/
│   ├── raw/            # 原始提取件（gzip 压缩存档，只读）
│   └── processed/      # 清洗后的岗位记录与排名结果
├── src/                # 管道脚本
│   ├── 00_local_receiver.py   # 浏览器取数时的本地接收服务（临时工具）
│   ├── 01_extract_feishu.js   # 在页面内执行的取数脚本（浏览器控制台注入）
│   ├── 02_build_records.py    # 原始 recordMap → 结构化 CSV
│   └── 03_filter_rank.py      # 技能匹配筛选与排序
├── docs/
│   ├── 数据字典.md      # 字段 ID → 中文名 → 选项标签
│   └── 方法说明.md      # 每一步怎么做、口径是什么
├── outputs/            # 对外交付物
└── logs/               # 逐日操作记录
```

## 快速开始

```bash
# 依赖：python3 + pandas + openpyxl；浏览器取数需 Chrome
pip3 install pandas openpyxl

# 从清洗后的数据重跑筛选与排序
python3 src/03_filter_rank.py

# 取新数据（需先在浏览器里打开目标多维表格，把 01_extract_feishu.js 注入控制台，
# 并先启动本地接收服务）
python3 src/00_local_receiver.py 8899
```

## 数据说明

- `data/raw/*.json.gz`：从飞书多维表格接口取回的原始响应（含 `recordMap` 与 `fieldMap`），**共 7,855 条记录、18 个字段**。

## 方法论要点（面试会被问）

| 问题 | 口径 |
|---|---|
| 数据怎么取的？ | 复用页面内的数据接口（同源 fetch ＋ 解压），不是 OCR、不是手工复制 |
| 去重口径？ | 公司名规范化（去括号/去「集团」「有限公司」等后缀）后比对，同一公司取最高分记录 |
| 「技能匹配」怎么算的？ | 正向职能词与负向技术词计分，净分排序；★ 标记为 JD 中**明确出现**「数据分析/商业分析」等字样的岗位 |
| 人的部分 vs AI 的部分？ | 需求拆解、字段口径、验收标准、结果校验与迭代 → 人；接口调用、解压、清洗脚本、渲染管线 → AI 执行 |
